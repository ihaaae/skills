# Progressive Learning

## 输入与输出

本技能没有显式的参数，输入就是当前 context 里已有的两样东西：

- **要学的知识点**：一个约 25 分钟（含练习）能学完的知识点，通常还带着它服务的学习目标。
- **学习者的知识基础**：学习者已经掌握了哪些概念。讲解、例子和所有题目的答案路径，只能用这些概念和当前知识点本身。

输出是一份完整的 topic 文档（Markdown 文件），以及按这份文档上完的一节课。文件放在哪里由 context 决定（例如工作区的约定）；context 没说时，问用户。

## 第一步：判断

先判断两件事，任何一件不满足，就不写文档，直接告诉用户：

- **这个知识点要不要超过 25 分钟。**需要超过四层的例子和题目，或者第一层的知识要引入两个以上的新术语，通常就超过了。说明它太大在哪里，可以怎样拆，不要勉强写。
- **学习者缺不缺前置。**讲解或某道题的答案要用到一个既不在知识基础里、也不属于这个知识点的概念时，说明缺的是什么。不要在课里用两句话顺手补上：顺手补上的内容没有经过检测，会变成后面课程的隐性依赖。

## 第二步：写 topic 文档

先把整节课写成文档，再开始上课。

文档必须照下面的结构写：标题的文字、编号方式和顺序都不能改，只有尖括号里的内容和标了"可省略"的模块由你决定。

```
## <知识点标题>
### 定位
### 阅读任务                  （阅读型才有）
### 知识
### 例子一：<术语化但准确的标题>
### 问题一
### 问题二
### 知识二：<这一段讲什么>     （可省略）
### 例子二：<……>
### 问题三
### 问题四
…                            （共 2～4 层）
### 延伸：<讲什么>             （可省略）
### 回到全景
## 答案与解析
### 问题一
…
```

- **一层 = 可选的知识N + 一个例子 + 两道题**，第一层的知识必需。每个知识点写 **2～4 层**，全景图类的知识点也一样，层数在这个范围内按知识点的大小定。原因：只有一层时，题目只能考最干净的模型，学不到它在现实里怎么用；超过四层，说明知识点太大，应该回到第一步。
- 题目只写题干和选项。答案集中放在文末的"答案与解析"里，这样学习者从头读文档时不会先看到答案。每道题的解析写清：正确选项和理由（沿用例子示范的那条思路逐步走），以及每个干扰项对应哪一步错误推理。上课时的反馈从这里取材。
- 题目编号在一份文档里连续递增，不因换层而重置；每份新文档从"例子一""问题一"重新开始。原因：用户说"问题三错了"时，编号必须在这份文档里有唯一的指向。

**阅读型知识点**（知识点要求学习者读一段指定的材料）也写 2～4 层，阅读时间算在 25 分钟里。和普通知识点只差两处：定位之后加 `### 阅读任务`，写明读哪篇、哪几节，预计 10～15 分钟，给 2～3 个带着读的引导问题；`### 知识` 不自己讲一遍材料，只用一两句话收拢材料要建立的主张，配一张图或表。之后的例子和题目只用这些主张，不考原文的其他细节：第一层考主张本身，后面的层把主张用到新场景。

写之前先读完两份参考，它们说明每一块怎么写：

- [modules.md](modules.md)：各模块（定位、知识、例子、问题、之后的每一层、延伸、回到全景）的写法
- [questions.md](questions.md)：题型（默认选择题）和出题要求

写完运行检查脚本，按它列出的问题改，直到打印"通过"：

```
uv run <skill-dir>/scripts/check_topic.py <topic 文档> [--reading]
```

`--reading` 用于阅读型知识点。脚本只查结构：模块顺序、层数、每层一个例子两道题、题号连续、答案只在文末、每道题都有解析、知识里有图或表。报"超过 4 层"时不要压缩层数凑数，回到第一步告诉用户。

脚本查不了内容，结构通过后再自查：每道题能不能只靠前面讲过的内容和学习者的知识基础解出来？只看例子里的推理步骤、不看它的结论，能不能解出这一层的两道题？

## 第三步：按文档上课

上课时按文档一块一块地发给学习者。发出的模块照抄文档里对应的那一块，标题照文档用 Markdown 三级标题写出来；不要临场改写、合并或跳过。问题解答从"答案与解析"取材，针对用户选的那个选项写。

**每一轮按下表走。**先看刚发生了什么，找到对应的一行，只发这一行写的内容，然后停：

| 刚发生了什么 | 这一轮发什么 | 然后 |
|---|---|---|
| 开始上课 | 定位 + 知识（阅读型：定位 + 阅读任务） | 停，等用户读完 |
| 阅读型：用户读完了材料 | 回答阅读时的疑问（只用知识基础和指定章节的内容）+ 知识 | 停，等用户读完 |
| 用户读完知识N | 例子N | 停，等用户读完 |
| 用户读完例子（或补充例子） | 这一层下一道还没出的题；文档里这一层的题出完了，就出补充问题 | 停，等回答 |
| 用户答了题，这一层最近两道题都答对 | 问题解答 + 下一层的第一块（知识N，没有就是例子N）；已是最后一层，就是延伸，没有延伸就是回到全景 | 停 |
| 用户答了题，没满足上一行，文档里这一层还有题 | 问题解答 + 这一层下一道题 | 停，等回答 |
| 用户答错，文档里这一层的题已出完 | 问题解答 + 补充例子：比原例子更简单或更接近，针对暴露出的误区重讲 | 停，等用户读完 |
| 用户答对，没满足"最近两道都答对"，文档里这一层的题已出完 | 问题解答 + 补充问题 | 停，等回答 |
| 用户读完延伸 | 回到全景 | 结束 |
| 用户提了问题，没有作答 | 回答问题 | 停在原地，不前进 |

- 一层掌握的标准是**这一层最近两道题都答对**。只有满足它，才能进入下一层；第一道对、第二道错，也不算掌握。
- 新内容（知识、例子、补充例子）停下时，用一句话收尾，如"读完有疑问就问，没问题就说继续"。题目从不和新内容放在同一轮：读不懂的地方会被题目带过去。
- 课上加的内容标题写 `### 补充例子一：<标题>`、`### 补充问题一`，单独编号，不占文档的题号。

问题解答写成 `### 问题解答N`（N 是这道题的编号，补充问题写"补充问题解答一"）：

- 先判断对错，不要只说"对"或"错"。
- 答对：简短点明他应用了哪条规律，必要时顺带说一句最有迷惑性的那个干扰项错在哪里。不必追问理由；怀疑是蒙的，下一道题就是验证。
- 答错：不要只公布正确答案。按例子示范的那条思路逐步对照，点出他所选选项背后错在哪一步，再回到最接近的例子。

课后把补充例子和补充问题连同解析，写进文档末尾的 `## 课上补充`（放在答案与解析之后），让文档反映实际教过的内容。
