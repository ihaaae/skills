# Progressive Learning

## 流程

复制这份清单，逐项勾选：

```
进度：
- [ ] 第一步：判断大小和前置，写分层计划并按清单自查；不通过才停下来问学习者
- [ ] 第二步：读 modules.md 和 questions.md，按计划写 topic 文档
- [ ] 第二步：check_topic.py 直到打印"通过"，再自查内容
- [ ] 第三步：用 lesson.py 按文档上课
- [ ] 课后：把补充例子和补充问题写进文档的"## 课上补充"
- [ ] 课后：装了 spaced-repetition skill、且这节课通过了，就按它起草 atom，让学习者批准
```

要继续一节已经开始的课（文档旁已有 `<文档>.progress.json`）时，直接到第三步，先运行 `status`。

## 输入与输出

本技能没有显式的参数，输入就是当前 context 里已有的两样东西：

- **要学的知识点**：一个约 25 分钟（含练习）能学完的知识点，通常还带着它服务的学习目标。
- **学习者的知识基础**：学习者已经掌握了哪些概念。讲解、例子和所有题目的答案路径，只能用这些概念和当前知识点本身。

下文的"学习者"就是对话里的用户。

输出是一份完整的 topic 文档（Markdown 文件），以及按这份文档上完的一节课。文件放在哪里由 context 决定（例如工作区的约定）；context 没说时，问学习者。

## 第一步：判断

先判断两件事：

- **这个知识点要不要超过 25 分钟。**需要超过四层的例子和题目，或者第一层的知识要引入两个以上的新术语，通常就超过了。
- **学习者缺不缺前置。**讲解或某道题的答案要用到一个既不在知识基础里、也不属于这个知识点的概念时，不要在课里用两句话顺手补上：顺手补上的内容没有经过检测，会变成后面课程的隐性依赖。

**先写出分层计划，按下面的清单逐条自查，再动笔写文档。**计划只要几行：每层一句话，说这一层比前一层多了什么，并列出这一层的新术语；最后写"本节不讲"，列出相邻知识点的内容。例如：

```
可以在 25 分钟内学完，前置都有。计划写 2 层：
- 第一层：三次握手的三条消息各自确认了什么（新术语：SYN、ACK）
- 第二层：同一条规律用到丢包场景，判断双方各能确定什么（不加新术语）
本节不讲：序号怎么递增、握手花多少时间（属于 T3）
```

自查清单（逐条写出结论，不只写"通过"）：

- 层数在 2～4 层之间；
- 第一层的新术语不超过两个；
- 每层的讲解和题目的答案路径，只用知识基础和本知识点；
- "本节不讲"和相邻知识点的范围对得上，没有为凑层数拉进相邻知识点；
- 各层的递进是真实的：后一层比前一层多一个因素或换一个场景，不是同一道题换个说法。

结果按下面处理：

- **全部通过**：把计划和自查结论简短写在回复里，备事后查看，不等学习者确认，直接进入第二步。
- **有一条不通过，能在计划里改掉**（比如把第一层的一个术语挪到第二层）：改完再查一遍。
- **知识点太大，或缺前置**：停下来，说明太大在哪里、可以怎样拆，或者缺的是哪个前置，按学习者的决定做，比如拆分、先学前置。这是学习者能回答、也只有学习者能决定的问题。

原因：学习者要求"写文档"时，很容易顺着请求直接写下去，把判断跳过；先写出计划再逐条自查，判断才真正起作用。第一层塞得太满、拉进相邻知识点凑层数，这些问题在计划里一眼就能看出来，改一行就行；写完整篇文档才发现，就得重写。不让学习者审计划，是因为学习者还没学这些内容，没有能力判断分层是否合适；能判断的依据（前置、已掌握的知识点、相邻知识点的范围）都在 context 里。写文档时照自查通过的计划写。

## 第二步：写 topic 文档

先把整节课写成文档，再开始上课。

文档必须照下面的结构写：标题的文字、编号方式和顺序都不能改，只有尖括号里的内容和标了"可省略"的模块由你决定。

```
## <知识点标题>
### 定位
### 阅读任务                  （阅读型才有）
### 知识
### 例子一：<术语化但准确的标题>
### 问题一
### 问题二
### 知识二：<这一段讲什么>     （可省略）
### 例子二：<……>
### 问题三
### 问题四
…                            （共 2～4 层）
### 延伸：<讲什么>             （可省略）
### 回到全景
## 答案与解析
### 问题一
…
```

- **一层 = 可选的知识N + 一个例子 + 两道题**，第一层的知识必需。每个知识点写 **2～4 层**，全景图类的知识点也一样，层数在这个范围内按知识点的大小定。原因：只有一层时，题目只能考最干净的模型，学不到它在现实里怎么用；超过四层，说明知识点太大，应该回到第一步。
- 题目只写题干和选项。答案集中放在文末的"答案与解析"里，这样学习者从头读文档时不会先看到答案。每道题的解析写清：正确选项和理由（沿用例子示范的那条思路逐步走），以及每个干扰项对应哪一步错误推理。上课时的反馈从这里取材。
- 题目编号在一份文档里连续递增，不因换层而重置；每份新文档从"例子一""问题一"重新开始。原因：学习者说"问题三错了"时，编号必须在这份文档里有唯一的指向。

**阅读型知识点**（知识点要求学习者读一段指定的材料）也写 2～4 层，阅读时间算在 25 分钟里。和普通知识点只差两处：定位之后加 `### 阅读任务`，写明读哪篇、哪几节，预计 10～15 分钟，给 2～3 个带着读的引导问题；`### 知识` 不自己讲一遍材料，只用一两句话收拢材料要建立的主张，配一张图或表。之后的例子和题目只用这些主张，不考原文的其他细节：第一层考主张本身，后面的层把主张用到新场景。

写之前先读完两份参考，它们说明每一块怎么写：

- [modules.md](modules.md)：各模块（定位、知识、例子、问题、之后的每一层、延伸、回到全景）的写法
- [questions.md](questions.md)：题型（默认选择题）和出题要求

写完运行检查脚本，按它列出的问题改，直到打印"通过"：

```
uv run <skill-dir>/scripts/check_topic.py <topic 文档> [--reading]
```

`--reading` 用于阅读型知识点。脚本只查结构：模块顺序、层数、每层一个例子两道题、题号连续、答案只在文末、每道题都有解析、知识里有图或表。报"超过 4 层"时不要压缩层数凑数，回到第一步告诉学习者。

脚本查不了内容，结构通过后再自查：每道题能不能只靠前面讲过的内容和学习者的知识基础解出来？只看例子里的推理步骤、不看它的结论，能不能解出这一层的两道题？

## 第三步：按文档上课

两个脚本都只用 Python 标准库（需要 3.11+），没有 `uv` 时可以用 `python3` 直接运行。

上课的进度由脚本管：它判选择题的对错、记住进度（存在文档旁边的 `<文档>.progress.json`）、决定这一轮发什么。你负责写它交给你的内容。

```
uv run <skill-dir>/scripts/lesson.py <topic 文档> start              开始上课
uv run <skill-dir>/scripts/lesson.py <topic 文档> continue           取出下一轮预先给出的内容（通常不用）
uv run <skill-dir>/scripts/lesson.py <topic 文档> answer C           学习者答了题（开放题由你判断，用 --correct yes|no）
uv run <skill-dir>/scripts/lesson.py <topic 文档> supplement --key B 登记你写的补充问题（开放题用 --open）
uv run <skill-dir>/scripts/lesson.py <topic 文档> status             查看进度
```

**学习者作答时先运行脚本，再照它的输出回复**；学习者说"继续"时，通常不用运行脚本：

- 输出里"—— 预先给出的 N 轮"之后，是学习者之后每说一次"继续"要发的内容，进度已经记好。学习者说继续，就按顺序直接发下一轮，不运行脚本。原因：每次运行脚本都要多一次模型调用，而"继续"之后发什么是确定的。忘了发到哪一轮，运行 `continue`，它按顺序取出还没发的那一轮。

- "照抄文档里的这一块"：原样发出，不改写、不合并、不跳过。
- "你来写"：按下面的要求写。补充问题写好后，先用 `supplement` 登记，再发出。
- "然后"：照做，到这里就停，不多发。
- 学习者提问、没有作答时，直接回答，不运行脚本，进度不变；预先给出的下一轮等学习者说继续再发。
- 不要凭记忆判断进度。不确定时运行 `status`。

你要写的内容：

- **问题解答**（标题 `### 问题解答N`，补充问题写 `### 补充问题解答N`）：先判断对错，不要只说"对"或"错"。答对：简短点明他用对了哪条规律，必要时顺带说一句最有迷惑性的那个干扰项错在哪里，不必追问理由。答错：不要只公布正确答案，按例子示范的那条思路逐步对照，点出他所选选项背后错在哪一步，再回到最接近的例子。脚本会附上答案与解析里这道题的解析，从那里取材。
- **补充例子**（`### 补充例子N：<标题>`）：比原例子更简单或更接近它，针对暴露出的误区重讲，同样写成题目 + 解答，末尾给判断方法。
- **补充问题**（`### 补充问题N`）：和这一层的例子同构，考同一个原理，不加新变量。

课上完后，脚本会提醒你把补充例子和补充问题连同解析，写进文档末尾的 `## 课上补充`（放在答案与解析之后）。

这节课不负责长期记住。课上讲过的事实要长期保留，交给 spaced-repetition skill：课后把它们写成 atom（学习者犯过的错尤其值得写），由 Anki 的 scheduler 决定什么时候复习。
