# 题型：默认用选择题

所有问题默认使用单选题，给 4～5 个选项，用 A、B、C、D、E 标注。原因是：开放式问题要用户每题打一段话，作答成本高，用户很快就会想跳过练习，而跳过的复测等于没做——两道同构题的检测效果恰恰依赖用户愿意把每道题都做完。选择题让作答只需一个字母，把用户的精力留给思考而不是打字。

蒙对的风险由流程本身抵消：4～5 个选项时单题蒙对概率约 20%～25%，同层两道复测都蒙对的概率只有约 5%。所以答对时不必追问理由；如果怀疑是蒙的，第二道复测题就是验证。

写好选项的要点：

- **每个干扰项对应一个具体的错误推理。**干扰项应当是“推理在某一步偏了”会得到的答案，例如混淆了两个相近概念、用了惯例而不是实际规则、把源和目标弄反、漏掉了一个条件。这样用户选错时，选项本身就说明了错在哪一步，问题解答可以直接针对那一步。随手凑数的干扰项既浪费选项，也让正确答案过于明显。
- **只有一个正确选项**。
- **不要让形式泄露答案**：正确选项不要系统性地更长、更精确或总在同一位置；避免“以上都对／都不对”。
- **选项要短**，最好一行以内，便于对比。
- **题干不要提前说出要考的规律**，否则选择题会退化成找原文。
- **题干里的量词要有唯一读法**："一轮""一次""一帧"这类词，在场景里可能指多种东西时（"一轮"是一个 tick，还是左右轮中的一个？），换成已讲过的术语，或在题干里说明。出完题自查一遍。
- **选项和题干的主谓宾、动词也要准**："作废""收到"这类词先确认主语是谁（作废的是帧，不是 node），动词在场景里会不会有几层意思（"收到"是 bit 到了 controller，还是软件拿到了 data？）。有歧义就换成说清那一层的说法。一个词定下含义后，整节课只用这一个含义；需要区分两层时，给两层各定一个词（如"听到" = bit 到了 controller，"accept" = controller 确认无错、交给本设备的程序），首次出现时定义。

一道题里有两三个需要分别判断的小问时，可以写成几个并列的小题，每个小题各自带选项，用户按“1B 2D”这样的格式作答；但小题不宜超过三个，否则又回到了高作答成本。

**动机题。**一个知识点的全部题目里至少一道（通常在第二层或之后）考"为什么"，而不只考"是什么"。最便宜的形式是反事实："如果约束 X 不存在，设计里哪一部分可以改？"或"如果改成 Y，会坏在哪？"。动机要先在知识或例子里讲过，这道题才成立。原因：只会用规则、不知道规则为什么存在的知识，换个场景就用不上，也最容易让人觉得学了没意义。

知识点是一张全景图（讲一个领域由哪几块组成、每块回答什么问题）时，用归类题："出现一个新需求，它归哪一块管？"，不考各块的细节。知识点是把几个已学内容放在一起比较或分类时，用迁移题：把这个分类或对比用到一个没讲过的对象上。

少数情况下可以改用开放式小问题：当这一层真正要检验的是“能否用自己的话说出原因”，或者答案是一个无法合理枚举的结构（如写出一个完整的包的源和目标）。即使这时，也尽量把要求压到一两句话或一两个填空，并且在一个知识点的全部题目里，开放式题目最多一两道。

文档和上课的语言都应耐心、清晰、简洁。**简洁不等于压缩**：每个新出现的说法、每一步推理都用完整的句子写出来，宁可多一句"这里的意思是……"，也不要用一个短语带过，让读者自己去补。压缩的语言读起来费力，用户会以为是自己没懂。避免堆砌定义、术语和长列表。
