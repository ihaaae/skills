# Writing for Learners

学习者读到的每一句话都在教他，包括课文、例子、题目、选项、问题解答、节点摘要和记忆卡片。学习者读不懂时，常常以为是自己没懂，不会怀疑是文字写坏了。所以文字的问题要由写的人先查出来。

下面的原则对课文和卡片都成立。各种体裁自己的写法（课文的模块、选择题的选项、卡片的形状）写在对应的 skill 里：progressive-learning 管课文和题目，writing-anki-cards 管卡片。

**学习者偏好优先。** context 里有学习者的偏好（如工作区 `AGENTS.md` 里的教学语言、术语用哪种语言、提到别的知识点怎么称呼），按偏好写；偏好和本文冲突时，以偏好为准。

## 原则

### 1. 只用学过的

讲解、例子和每道题、每张卡片的答案路径，只能用学习者已掌握的知识和当前这一课讲过的内容。需要的事实没讲过，就写进题干或卡片正面，不要指望学习者去查材料。

原因：学习者不读材料。答案依赖一个没讲过的细节时，学习者答不出来，也不知道缺的是什么，整节课会停在这里。

### 2. 一个东西一个词，一个词一个意思

- 同一个东西全程只用一个词：用了「字符」就不再换成「文字」，用了 code point 就不再换成「码位」。换词时，读者会以为是两样东西。
- 一个词定下含义后只用这个含义。一个词在场景里可能有几层意思时（「收到」是 bit 到了 controller，还是软件拿到了 data？），给每一层各定一个词，首次出现时定义。
- 量词也一样：「一轮」「一次」「一帧」在场景里能指多种东西时，换成讲过的术语，或当场说明指哪一个。
- 动词先确认主语：作废的是帧，不是 node。

### 3. 措辞和事实一样宽

「只能」「没有」「都」「从不」这类全称说法，只在确实没有例外时用。拿不准就写清范围：写「除 PDO 外都能用」，不写「只能走 SDO」。

原因：全称说法一旦被后文的例外推翻，学习者会以为前后矛盾，连带不信前面学过的内容。

同理，连接词（「可是」「所以」「而且」「也就是」）要和实际的逻辑关系一致。不同层次的概念不用「也就是」画等号：rune 是 type，UTF-32 是 encoding，两者不能互相替换。

### 4. 不造词

分类、步骤、地图一律用领域的标准术语，或直接用一句话描述（「等 CPU 的那段等待」）。不起「四关」「甲乙丙」「类 PDO」这类名字，也不让题目或卡片依赖它们。需要编号时只在当场的一张表里用，不带出表外。

原因：自造的词看起来像术语，学习者会去记它，以为业界也这么叫；离开这节课它就没用，还会和真术语混在一起。

一个新说法确实需要时，先用完整的句子说清它指什么，再使用。标题里不出现正文还没解释过的说法。

### 5. 说清操作本身

- **用语言自己的操作名描述代码**：「赋值给 interface 变量」「传参数」「返回」，不用「放进」「装进」「塞到」这类空间比喻。空间比喻让读者去猜对应哪个操作。
- **不用有歧义的词指代或描述**：「结果」「变长」「画成」「在哪一层」这类词，换成英文术语或直接说清操作（「`len(s)` 的返回值」「slice 的 length 增加了」）。
- **不写空话**：「byte 的 type 是 byte」这类句子没有信息量，删掉或改成真正要说的事。
- **避免能读成两种意思的句式**，如「X 不是 Y 的 type」（是「X 的 type 不是 Y」，还是「X 不是一个 type，而 Y 是」？）。换成只有一种读法的说法。

### 6. 例子具体、自包含

- 先给一个具体的例子，再给抽象的规则；能用「这段代码打印什么」问的，不用抽象描述问。
- **例子自包含**：代码里用到的每个变量、type、struct、interface、method，都写出完整的声明。读者不应该需要回到别处去找定义。
- 能用学习者自己课上的例子，就用它，包括他犯过的错。

### 7. 易混的东西并排对照

两个容易混淆的东西（`[]byte(s)` 和 `[]rune(s)`，「听到」和「accept」），写的时候让它们并排出现、措辞明显不同，并让题目或卡片必须区分它们才能答对。只讲其中一个时，学习者会把另一个也套进来。

### 8. 简洁不等于压缩

每个新出现的说法、每一步推理，都用完整的句子写出来。宁可多一句「这里的意思是……」，也不要用一个短语带过，让读者自己去补。压缩的语言读起来费力，学习者会以为是自己没懂。

简洁指的是删掉不帮助理解的东西：重复的铺垫、和这一课无关的术语、长长的定义列表。不是把推理压成几个词。

## 自查清单

写完、给学习者看之前，逐条查：

```
- [ ] 每个事实都在学习者已掌握的知识、这一课讲过的内容，或题干/卡片本身里
- [ ] 同一个东西只用一个词；每个词、每个量词在场景里只有一种读法
- [ ] 全称说法（只能/都/从不）确实没有例外；连接词和逻辑关系一致
- [ ] 没有自造的词；标题里没有正文没解释过的说法
- [ ] 代码用操作名描述；没有歧义词、空话、两读句式
- [ ] 代码例子自包含
- [ ] 易混的东西被并排对照
- [ ] 每步推理都是完整的句子
- [ ] 符合 context 里的学习者偏好
```
